# Megatron-LM Monthly Activity Report — November 2026 (through November 1, 2026)

> Chinese version: [中文版本](https://github.com/lhb8125/megatron-lm-activity-report/blob/main/reports/zh-CN/2026/11.md)

## Overview

Delivered work improves MFSDP communication overlap and MXFP8 recomputation while strengthening ScheduleNode activation ownership. Ongoing work advances MoE routing and execution, collection-aware process-group handling, MFSDP pipeline tracing, and Transformer Engine compatibility.

- Substantive PR activity after filtering: opened 5; merged 13; closed without merge 5; active at cutoff 56.
- Excluded from the report and statistics: test-only 0, CI-only 1, test/CI-only 1, format-only 0.

## Delivered

### MFSDP gradient communication overlap

MFSDP v2 separates outer gradient reduction onto a dedicated stream and exposes independent overlap controls.

- DP-outer gradient reduction now uses a dedicated stream, allowing it to overlap subsequent inner reductions without adding a gradient buffer. ([main #6973](https://github.com/NVIDIA/Megatron-LM/pull/6973))

### MFSDP MXFP8 recomputation

MFSDP recomputation now supports gathering the MXFP8 data required outside an owning FSDP module.

- Refined recomputation tests and renamed the opt-in schedule setting to gather all MXFP8 planes during backward, providing access to rowwise and columnwise MXFP8 data. ([main #8432](https://github.com/NVIDIA/Megatron-LM/pull/8432))

### ScheduleNode activation ownership

ScheduleNode activation handling retains storage-independent ownership for releasable inputs and grouped tensors.

- Synchronized the autograd-boundary branch with main while retaining ownership that supports MXFP8 grouped tensors and dispatch buffers without storage resizing for manual release. ([main #8302](https://github.com/NVIDIA/Megatron-LM/pull/8302))

## In Progress

### MoE routing and execution

MoE work is improving inference overlap, deterministic expert combining, chunked execution, and batch-invariant routing.

- Shortcut MoE inference gains opt-in CUDA-graph-compatible overlap between routing and attention or GDP branches, while serial inference remains the default. ([main #8257](https://github.com/NVIDIA/Megatron-LM/pull/8257))
- An opt-in fixed FP32 reduction tree provides EP-invariant combining for batch-invariant MoE routing. ([main #8261](https://github.com/NVIDIA/Megatron-LM/pull/8261))
- Chunked MoE execution keeps call counts fixed and replays per-chunk routing to avoid expert-parallel deadlocks and preserve recomputation behavior. ([main #8463](https://github.com/NVIDIA/Megatron-LM/pull/8463))
- A shared Triton sigmoid top-k path aligns batch-invariant routing behavior across supported training and inference configurations. ([main #8602](https://github.com/NVIDIA/Megatron-LM/pull/8602))

### Core process-group ownership

Core training and checkpoint paths are moving communication and auxiliary operations onto each run’s process-group collection while exposing global-grid fallbacks.

- Core helpers now warn when omitted process groups resolve to the global grid, including attention, inference, CUDA-graph, MoE, and logging paths. ([main #8755](https://github.com/NVIDIA/Megatron-LM/pull/8755))
- Training-loop helpers use collection-based data-parallel selection and propagate the collection through model setup, reductions, optimizer use, and auxiliary checks. ([main #8757](https://github.com/NVIDIA/Megatron-LM/pull/8757))
- Checkpoint metadata, RNG, dataloader, and gradient-dump handling now use collection-aware groups instead of silently defaulting to the global grid. ([main #8758](https://github.com/NVIDIA/Megatron-LM/pull/8758))

### Process-group registry and enforcement

Process-group migration work is extending registry-based bootstrap, automated checking, and end-to-end validation for custom grids.

- Bootstrap initializes from registered process-group collections and constructs all-gather groups with support for framework-created groups, expert GTP, and nondefault rank orderings. ([main #8768](https://github.com/NVIDIA/Megatron-LM/pull/8768))
- Process-group checker enforcement classifies global-grid reads and updates CI checks for warned, guarded, and unwarned fallback paths. ([main #8770](https://github.com/NVIDIA/Megatron-LM/pull/8770))
- An integration test exercises model build, DDP, optimization, training, checkpointing, and inference on a non-global grid under strict fallback and deprecation settings. ([main #8771](https://github.com/NVIDIA/Megatron-LM/pull/8771))
- Tree-wide CI checks cover hidden aliases, private global reads, ignored warnings, and functional-test coverage so process-group fallback policies are merge-enforced. ([main #8773](https://github.com/NVIDIA/Megatron-LM/pull/8773))

### MFSDP pipeline execution tracing

MFSDP execution-order recording is being extended to validate complete pipeline schedules.

- Execution-order recording now spans complete PP/VPP pipeline windows, including multiple backward calls and forward/backward transitions, through a shared cursor and lookahead. ([main #8778](https://github.com/NVIDIA/Megatron-LM/pull/8778))

### Transformer Engine 2.21 compatibility

Transformer Engine compatibility work updates the engine baseline and adapts sharded LayerNormLinear gradients and affected references.

- Transformer Engine is pinned to the release_v2.21 tip; LayerNormLinear dummy weight gradients use local parameter shapes, and affected numerical, inference, and CUDA-graph references are refreshed. ([main #8807](https://github.com/NVIDIA/Megatron-LM/pull/8807))
