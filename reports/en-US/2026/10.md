# Megatron-LM Monthly Activity Report — October 2026 (through October 11, 2026)

> Chinese version: [中文版本](https://github.com/lhb8125/megatron-lm-activity-report/blob/main/reports/zh-CN/2026/10.md)

> Reporting window: 2026-10-01 through 2026-10-11 (Asia/Shanghai); source: [`NVIDIA/Megatron-LM`](https://github.com/NVIDIA/Megatron-LM).

## Overview

Delivered work strengthened attention and distributed-training correctness, expanded MFSDP and model capabilities, and improved CUDA-graph, MoE, multimodal, and inference reliability. Ongoing work advances custom parallel topologies, MFSDP and checkpointing, CUDA Graph reliability, inference execution, hybrid model features, and MoE performance.

- Substantive PR activity after filtering: opened 277; merged 98; closed without merge 44; active at cutoff 335.
- Excluded from the report and statistics: test-only 29, CI-only 26, test/CI-only 7, format-only 0.

## Delivered

### MLA RoPE and fused attention correctness

Attention kernels and fused normalization paths received race-safety, masking, and execution-path fixes for packed and sliding-window workloads.

- Fused MLA Q-RoPE kernels now insert barriers between source loads and overlapping in-place stores, while per-head bounds use absolute indices to prevent partial-block accesses from reaching neighboring token rows. ([main #5963](https://github.com/NVIDIA/Megatron-LM/pull/5963), [main #6890](https://github.com/NVIDIA/Megatron-LM/pull/6890), [dev #7789](https://github.com/NVIDIA/Megatron-LM/pull/7789))
- Sliding-window attention now uses the masking-aware PyTorch softmax path instead of Apex fused kernels that could silently apply full causal attention. ([main #7850](https://github.com/NVIDIA/Megatron-LM/pull/7850))
- The fused MLA pre-MLP normalization specification exposes the residual input, enabling Transformer Engine’s fused residual RMSNorm backward path, and MLA down-projection preparation uses a vectorized tiled copy kernel for row-strided Q and KV inputs. ([main #7942](https://github.com/NVIDIA/Megatron-LM/pull/7942), [main #7957](https://github.com/NVIDIA/Megatron-LM/pull/7957))

### MFSDP v2 checkpointing and distributed layouts

MFSDP v2 expanded optimizer checkpoint support and strengthened layout construction, communication, conversion, and delayed-gradient handling.

- MFSDP v2 optimizer state now supports DCP save and load in the shared fsdp_dtensor format, including empty-local-shard placeholders, while Torch-dist to FSDP-DTensor conversion handles embedded common state and fused Gated DeltaProduct projection keys. ([main #6215](https://github.com/NVIDIA/Megatron-LM/pull/6215), [main #7674](https://github.com/NVIDIA/Megatron-LM/pull/7674))
- DBuffer and TensorAtomic support now covers multi-axis and uneven layouts, including zero-owned-tensor ranks, and fully_shard constructs TensorAtomic layouts from parameter-owner assignments while preserving parameter ordering and tied parameters. ([main #7633](https://github.com/NVIDIA/Megatron-LM/pull/7633), [main #7671](https://github.com/NVIDIA/Megatron-LM/pull/7671), [main #7672](https://github.com/NVIDIA/Megatron-LM/pull/7672))
- MFSDP v2 makes delayed weight-gradient synchronization ownership explicit so MCore completes reductions before optimizers consume the gradients. ([main #7854](https://github.com/NVIDIA/Megatron-LM/pull/7854))

### CUDA Graph capture and Triton determinism

Initialization and capture paths now provide more predictable kernel configuration and runtime RNG behavior.

- A packaged Triton autotune policy pins covered in-tree kernel configurations under deterministic mode so Mamba, MLA RoPE, mHC, and core autotuners select consistent non-timed configurations across ranks. ([main #6076](https://github.com/NVIDIA/Megatron-LM/pull/6076))
- CUDA graph capture now probes and caches lazy generator-registration support, while full-iteration capture primes CUDA generator states on newer PyTorch versions to prevent lazy Philox initialization from invalidating multi-stage capture. ([main #7800](https://github.com/NVIDIA/Megatron-LM/pull/7800), [main #7885](https://github.com/NVIDIA/Megatron-LM/pull/7885))

### MoE dispatch and distributed routing reliability

MoE dispatch gained backend and routing compatibility improvements, while collective exchange and scratch-buffer reuse became safer.

- Flex dispatch supports a DeepEP v2 backend with deterministic replay coverage and consumes Transformer Engine dense top-k routing indices when available, retaining boolean-map compatibility paths. ([main #5153](https://github.com/NVIDIA/Megatron-LM/pull/5153), [main #6615](https://github.com/NVIDIA/Megatron-LM/pull/6615))
- MoE auxiliary and sequence-auxiliary loss reductions now use each packed microbatch’s runtime context-parallel topology and local valid-token counts, including uneven token distributions. ([main #7046](https://github.com/NVIDIA/Megatron-LM/pull/7046))
- HybridEP routing exchanges now use NCCL all-gather instead of the timeout-prone custom kernel, and recycled GTP wgrad scratch buffers carry completion events that are honored by the next writer stream at checkout. ([main #7771](https://github.com/NVIDIA/Megatron-LM/pull/7771), [main #7927](https://github.com/NVIDIA/Megatron-LM/pull/7927))

### Muon and wide residual-stream model support

Model architecture work preserved logical attention updates and integrated wide residual streams across auxiliary and ShortcutMoE paths.

- Muon adds per-head QKV orthogonalization and reconstruction for TP-fragmented QKV layouts, including MLA and GTP-rematerialization cases. ([main #6326](https://github.com/NVIDIA/Megatron-LM/pull/6326), [dev #7085](https://github.com/NVIDIA/Megatron-LM/pull/7085))
- Wide residual streams now compose with MTP and MIMO while retaining ordinary-width auxiliary and modality paths, and ShortcutMoE supports wide residual input/output views, residual replay, MTP/MIMO composition, and FP32 residuals. ([main #6855](https://github.com/NVIDIA/Megatron-LM/pull/6855), [main #7440](https://github.com/NVIDIA/Megatron-LM/pull/7440))

### Mamba continuation state and inference caching

Inference state handling now protects recurrent transitions, partial-prefill boundaries, cache epochs, and short-sequence execution.

- Hybrid inference recomputes continuation chunks when matching attention KV blocks lack a usable Mamba state boundary, preventing cached attention prefixes from skipping recurrent transitions. ([main #7714](https://github.com/NVIDIA/Megatron-LM/pull/7714))
- Mamba snapshot extraction uses the scan’s actual chunk indices for context-aligned partial prefills, and inference enforces a minimum published FlashAttention query length of two instead of clamping prefill chunks. ([main #7755](https://github.com/NVIDIA/Megatron-LM/pull/7755), [main #7905](https://github.com/NVIDIA/Megatron-LM/pull/7905))
- After model refit, unprefilled requests are re-salted and re-hashed so new requests cannot match KV or Mamba blocks produced under the previous weight epoch. ([main #7891](https://github.com/NVIDIA/Megatron-LM/pull/7891))

### MIMO and multimodal checkpoint inference

Multimodal and MIMO inference paths gained checkpoint loading, model resolution, and rank-safe checkpoint discovery support.

- Dynamic inference can load MIMO-trained VLM checkpoints into LLaVAModel by remapping nested MIMO state-dict keys and exposing vision configuration overrides; Nemotron loading and inference paths were also updated for revised mappings, hybrid blocks, and wide residuals. ([main #7752](https://github.com/NVIDIA/Megatron-LM/pull/7752), [main #7839](https://github.com/NVIDIA/Megatron-LM/pull/7839))
- MTP now resolves the underlying language model through a generic helper for multimodal wrappers, and MIMO checkpoint directories are resolved on every rank before rank-zero metadata reads to avoid checkpoint-completeness deadlocks. ([main #7940](https://github.com/NVIDIA/Megatron-LM/pull/7940), [main #7941](https://github.com/NVIDIA/Megatron-LM/pull/7941))

### Low-precision and inference kernel optimizations

Precision controls and fused kernels reduced unnecessary work while preserving supported optimizer, expert, and inference behaviors.

- DSA projection paths now independently control FP8/FP4 participation and BF16 or FP32 outputs, while ModelOpt supports a separate learning rate and expert-parallel reduction metadata for NVFP4 LSQ scale parameters. ([main #6842](https://github.com/NVIDIA/Megatron-LM/pull/6842), [main #7802](https://github.com/NVIDIA/Megatron-LM/pull/7802))
- GDP padding writes and vLLM MoE counter initialization are fused into preceding kernels, paged-stash launch geometry is configurable, and fused shared-expert and residual additions use one Triton kernel when eligible. ([main #7841](https://github.com/NVIDIA/Megatron-LM/pull/7841), [main #7897](https://github.com/NVIDIA/Megatron-LM/pull/7897), [main #7943](https://github.com/NVIDIA/Megatron-LM/pull/7943))
- Precision-aware FP8 optimizer selection now retains the optimized path when parameters remain BF16 and are not gathered as FP8, avoiding unnecessary MCore FP32 gradient copies. ([26.09-beta #7915](https://github.com/NVIDIA/Megatron-LM/pull/7915))

Hybrid execution is gaining EP overlap, dynamic context parallelism, MTP scheduling, and generalized tensor-parallel infrastructure.

- HybridStack adds bracketed layer groups, independent FSDP units, and layer-granular expert-parallel communication overlap; EP overlap also supports segment-level activation recomputation. ### MoE routing, dispatch, and packed-sequence accounting

MoE work improves virtual-expert balancing, dispatcher safety, and auxiliary-loss handling for packed and delayed-gradient paths.

- Virtual expert replicas and HybridEP dispatch support MoonEP-style load balancing while preserving native expert ownership for weights, gradients, DDP, and checkpointing. ([main #7450](https://github.com/NVIDIA/Megatron-LM/pull/7450))
- NVLS dispatcher masking handles large token rows correctly, and packed THD sequences receive sequence-level auxiliary-loss accounting without dense sequence materialization. ### Memory-efficient recurrent execution and optimizer numerics

Recurrent kernels and optimizer paths are being optimized for lower movement, stable accumulation, and batch-invariant arithmetic.

- Activation reload synchronization, GDN decode slot-indexed kernels, and batch-invariant GDN/GDP arithmetic improve offload safety, recurrent-state movement, and fixed-block numerical behavior. ([main #7399](https://github.com/NVIDIA/Megatron-LM/pull/7399), [main #7896](https://github.com/NVIDIA/Megatron-LM/pull/7896), [main #7917](https://github.com/NVIDIA/Megatron-LM/pull/7917))
